# v3.5.2 对话解读

本轮调整解读的交流节奏和续聊操作，不更换排盘引擎、塔罗抽牌算法或后台计量路径。

## 公开资料参考

查阅日期：2026-11-05。以下是具体从业者或教学站点的做法，不代表所有流派，也不构成预测准确性的证明。

- [Biddy Tarot：一次专业解读的实际流程](https://biddytarot.com/blog/behind-the-scenes-tour/)：确认问题与牌阵，扫描整组牌的关联，再结合牌位解释，留出澄清与反馈空间。
- [Labyrinthos：如何读塔罗](https://labyrinthos.co/pages/how-to-read-tarot-cards)：将牌作为组合成故事的语言。采用关联表达方法，不照抄自我探索式反问流程。
- [iztro：星盘结构与解盘步骤](https://docs.iztro.com/learn/astrolabe)：关注宫位之间的关系，再根据问题进入相应宫位和运限。
- [澄慧紫微：流年咨询流程](https://zmdot.com/product/year_analysis/)：以出生信息、咨询内容和具体问题准备咨询，结合大限与流年讨论。

## 实现

`src/lib/reading-style.ts` 的公共交流规则由浏览器直连紫微与后台紫微共用，塔罗复用交流规则并保留独立牌阵约束。默认先回应眼前的问题、说明关键依据，再自然联系实际处境。篇幅服从用户要求，全盘、详细或逐张解读仍应完整响应。不靠悬念、恐吓、假装真人或反复反问延长对话。

- 紫微关联宫位，区别本命、阶段与年度数据，保留实际工具查询。
- 塔罗结合实际牌位、正逆位与整组牌；追问保持原牌阵，不自动抽牌，不替他人断定真实想法。
- 用户纠正时承接新信息、修正解释，不把推断当作个人事实或长期记忆。
- `ReadingReply` 提供按话题继续、选中文字追问、选择段落追问，只追加可编辑草稿，不覆盖已有输入或自动请求模型；主动发送才进入现有任务和用量管理。
- 抽牌前展示各牌位将解答什么，并提示可补充的背景，不增加必填问卷。
- 修复手机紫微导航竖排及塔罗入口因旧首项样式被隐藏的问题。
